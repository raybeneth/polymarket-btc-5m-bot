## 根因:订单簿失衡符号与市场微观结构相反

方向信号由两部分加权:动量(65%)+ **订单簿失衡(35%)**。失衡分量来自 `OrderBook.imbalance()`:

```python
# 修复前(错误)
# 注释称"卖单堆积 = 买家激进 = 看涨"
return (ask_vol - bid_vol) / total
```

这与标准微观结构相反:

- **bid(买单挂单)= 需求/支撑**,买单堆积 → 价格上行压力 → **看涨**
- **ask(卖单挂单)= 供给/压制**,卖单堆积 → 价格下行压力 → **看跌**

正确定义应为 `(bid_vol - ask_vol) / total`。

### 为什么会导致"上涨时高置信度押 NO"

上涨行情逐笔推演(修复前):

```
BTC↑ → YES("涨")代币被抢 → YES 买单堆积 → yes_imb=(ask−bid)/total < 0
        NO("跌")代币被抛  → NO 卖单堆积  → no_imb =(ask−bid)/total > 0
net = yes_imb − no_imb = (负) − (正) = 强烈负值 → 看跌 → 押 NO
```

趋势越干净,盘口失衡幅度越大 → **置信度越高**,精确匹配 dir=61~64 的错单。动量分量(65%)其实读对了(看涨 YES),被反向的 35% 拖过界,最终押了 NO。

## 改动

### 1. `feeds/polymarket_clob.py` — `OrderBook.imbalance()`

```python
# 修复后
return (bid_vol - ask_vol) / total   # 买单堆积 = 需求 > 供给 = 看涨
```

`+1 = 买单主导(看涨)`,`-1 = 卖单主导(看跌)`。同步修正 docstring/注释语义。

### 2. `filters/direction.py` — `_compute_ob_imbalance_score()`

组合公式 `net = yes_imb - no_imb` 在符号修正后**自动变正确,逻辑未改**。仅更新被写反的 docstring/注释(原文"piling into YES asks → bullish"是错的)。

修复后同场景验证:

```
上涨:YES 买单多 → yes_imb > 0;NO 卖单多 → no_imb < 0
net = (正) − (负) = 强正 → 看涨 YES ✓   (与动量一致)
```

> 未改权重(动量 0.65 / 订单簿 0.35),未动平滑窗口的全局 `_score_history`,以便本次修复效果可被独立观测。

## 风险与注意事项

1. **本次仅修符号,不加额外过滤层**,目的是隔离验证"押反"是否确由此 bug 引起——两处同时改会让效果难以归因。
