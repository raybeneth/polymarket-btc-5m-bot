## 改动一：direction / timing 硬性最低分门槛

### 病根

权重调整只能"惩罚"低分，无法"一票否决"。direction=1.8（LOSS #2）和 timing=1.0（LOSS #3）在综合评分中仅被扣几分，但其他高分（odds=92.5、chase=100）轻松补回，总分仍过 55 门槛。

这类交易的本质问题是：**在没有方向 edge 或在错误时机入场，即使价格再好也不该交易**。

### 改动

新增配置（`config.py`）：

```python
MIN_DIRECTION_FILTER_SCORE = 15.0   # direction 评分 < 15 → 直接 skip
MIN_TIMING_FILTER_SCORE = 20.0      # timing 评分 < 20 → 直接 skip
```

在 `main.py` 的过滤器流水线中，direction 和 timing 各自通过原有 pass/fail 判断后，额外检查分数是否达到硬性门槛。低于门槛直接短路跳过，不进入后续评分。

### 回测验证

| 订单 | direction | timing | 是否被拦截 |
|------|-----------|--------|-----------|
| 5b18b1d6 (LOSS #2) | **1.8** | 99.5 | ✓ direction < 15 拦截 |
| b682da4b (LOSS #3) | 55.5 | **1.0** | ✓ timing < 20 拦截 |
| a6861798 (LOSS #4) | **13.1** | 56.7 | ✓ direction < 15 拦截 |
| 31f549b2 (LOSS #1) | 47.5 | **16.4** | ✓ timing < 20 拦截 |
| a25e6959 (WIN) | 41.9 | 10.6 | ✗ timing < 20 会被拦截（误杀） |

注意：WIN 中的 a25e6959（timing=10.6）会被新门槛误杀。这是更严格准入的代价——放弃少数"碰运气赢了"的交易，换取过滤掉大部分低质量入场。

## 改动二：到期前强制平仓

### 病根

LOSS #1（31f549b2）的 token 中间价在持仓期间未跌破止损线（0.52 - 0.10 = 0.42），但到期时直接结算为 0.00，全亏 $1.00。这是二元期权的特殊风险：**中间价可能在到期前保持稳定，结算时突然跳变到 0 或 1**。

止损只能保护"渐变式"亏损，对"跳崖式"到期结算无效。

### 改动

新增配置（`config.py`）：

```python
FORCE_EXIT_BEFORE_EXPIRY = 30   # 距结算 ≤30s 时强制以 best_bid 平仓
```

在 `execution/order_manager.py` 的 `check_early_exits()` 中新增第三个触发条件：

```
触发优先级：
  1. best_bid <= entry_price - 0.10  → STOP_LOSS
  2. best_bid >= entry_price + 0.15  → TAKE_PROFIT
  3. 距结算 ≤ 30s                    → FORCE_EXIT（以当前 best_bid 卖出）
```

### 效果分析

以 LOSS #1 为例（NO @ 0.52）：
- 原来：持仓到期，结算 0.00，亏 $1.00
- 现在：距结算 30s 时强制平仓，假设 best_bid 仍在 0.45~0.55 附近
  - 如果 best_bid = 0.45 → 亏 $0.13（比 $1.00 少 87%）
  - 如果 best_bid = 0.50 → 亏 $0.04（几乎持平）
  - 如果 best_bid = 0.55 → 赚 $0.06（意外盈利）

关键：**即使强制平仓的价格不理想，也远好于赌到期的 0/1 二元结果**。

### positions.log 日志格式

```
[2026-07-01 xx:xx:xx] 平仓 | 模式=模拟 | 订单=PAPER-xxx | ... | 结果=LOSS(FORCE_EXIT)
```

## 改动三：收紧价格硬上限

### 病根

LOSS #5（1585a004）入场价 0.73，direction=67 看似不错但方向判反，价格暴跌到 0.47。入场价越高：
- 最大利润越小（0.73 入场最多赚 0.27/share）
- 止损触发时的绝对亏损越大（0.10 delta 在 0.73 入场 = 13.7% 容忍度）
- 方向判错的代价越大

### 改动

```python
ODDS_MAX_PRICE: 0.78 → 0.72
```

同时动态上限 `ODDS_DYN_MAX_WEAK` 保持 0.60 不变，因此：
- 方向=0 → 上限 0.60（不变）
- 方向=50 → 上限约 0.66（原 0.69）
- 方向=100 → 上限 0.72（原 0.78）

### 回测验证

| 订单 | 入场价 | direction | 旧动态上限 | 新动态上限 | 结果 |
|------|--------|-----------|-----------|-----------|------|
| 1585a004 (LOSS #5) | 0.73 | 67.0 | 0.72 | **0.68** | ✓ 被拦截（0.73 > 0.68） |
| 38dac168 (WIN) | 0.72 | 61.2 | 0.71 | **0.67** | ✗ 被误杀（0.72 > 0.67） |

LOSS #5 被成功拦截。WIN 中的 38dac168（入场 0.72）也会被拦，这笔赚了 $0.22，但同类高价入场交易长期看盈亏比不佳，牺牲是合理的。

## 三项改动的协同效应

| 防线 | 拦截的问题 | 涉及亏损 |
|------|-----------|---------|
| direction 硬性门槛 < 15 | 无方向 edge 的交易 | LOSS #2、#4 |
| timing 硬性门槛 < 20 | 错误时机入场 | LOSS #1、#3 |
| 到期前强制平仓 ≤ 30s | "跳崖式"到期全亏 | LOSS #1 |
| 价格上限 0.72 | 高价入场放大亏损 | LOSS #5 |

5 笔亏损中：
- 4 笔会被硬性门槛直接拦截（#1、#2、#3、#4）
- 1 笔会被价格上限拦截（#5）
- LOSS #1 有双重保护（timing 门槛 + 强制平仓）

---

## 风险与注意事项

1. **交易频次下降**：更严格的门槛会过滤掉更多交易机会。如果发现长时间无交易，可考虑将 `MIN_DIRECTION_FILTER_SCORE` 降至 10 或 `MIN_TIMING_FILTER_SCORE` 降至 15。
2. **强制平仓的滑点**：距结算 30s 时 orderbook 可能流动性变差，best_bid 可能偏低。但即使以较差价格卖出，也远好于赌 0/1 的二元结果。
3. **ODDS_MAX_PRICE 收紧后的动态上限**：方向满分（100）时上限也只到 0.72，某些高概率市场（如 BTC 大涨后的 YES 价格 0.75）会被拦下。如果错过太多高确定性机会，可考虑回调到 0.75。
