## 背景：模拟交易复盘暴露系统性亏损

对 `positions.log` 的 6 笔已平仓模拟交易做全面复盘：

| 指标 | 数值 |
|------|------|
| 总交易 | 6 笔 |
| 胜/负 | 2/4（胜率 33%） |
| 总盈利 | +$0.947 |
| 总亏损 | -$4.000 |
| **净盈亏** | **-$3.053** |

4 笔亏损交易的分项得分：

| 订单 | 方向 | direction | timing | odds | spread | chase | 综合 | 结果 |
|------|------|-----------|--------|------|--------|-------|------|------|
| 6a1c64fb | NO | 15.9 | **5.1** | 87.5 | 85.0 | 100.0 | 51.0 | LOSS |
| 953d778f | NO | 51.2 | **1.1** | 70.0 | 85.0 | 100.0 | 58.3 | LOSS |
| b3fb112c | NO | 63.1 | **29.0** | 67.5 | 85.0 | 100.0 | 66.1 | LOSS |
| e9842ba5 | YES | 33.8 | **30.1** | 82.5 | 85.0 | 100.0 | 59.7 | LOSS |

暴露 4 个系统性问题：

1. **timing 极低仍通过**：4 笔亏损 timing 分别为 5.1、1.1、29.0、30.1，但 timing 权重仅 15%，被 spread（85）和 chase（100）稀释
2. **spread/chase 无区分力**：几乎恒定 85 和 100，占 25% 权重但不提供任何过滤能力
3. **无止损机制**：赢 +$0.41~$0.54，输固定 -$1.00（持仓到期），盈亏严重不对称，需 >65% 胜率才能盈亏平衡
4. **方向信号噪音大**：120s 回看 + 30s/90s MA 在 300s 市场中窗口过短

---

## 改动一：评分权重重构

### 病根

spread（几乎恒定 85 分）和 chase（恒定 100 分）合计占 25% 权重，每笔交易白送约 18.5 分底分。timing 只有 15% 权重，即使评 1.1 分也仅扣 ~2.2 分综合分。加上 `MIN_COMBINED_SCORE=50` 门槛过低，垃圾交易轻松通过。

### 改动

| 过滤器 | 旧权重 | 新权重 | 原因 |
|--------|--------|--------|------|
| direction | 0.35 | **0.35** | 保持，核心信号 |
| odds | 0.25 | **0.20** | 略降，让出给 timing |
| timing | 0.15 | **0.25** | 大幅提升，timing 低分的交易全亏 |
| spread | 0.15 | **0.10** | 降低，恒定 85 无区分力 |
| chase | 0.10 | **0.10** | 保持 |

同时 `MIN_COMBINED_SCORE` 从 50.0 → **55.0**，收紧准入门槛。

### 验证：回测亏损交易

用新权重重新计算 4 笔亏损交易的综合分：

| 订单 | 旧综合分 | 新综合分 | 新门槛55 | 结果 |
|------|---------|---------|----------|------|
| 6a1c64fb | 51.0 | **44.8** | ✗ 拦截 | 原本放行的垃圾交易被拦下 |
| 953d778f | 58.3 | **51.3** | ✗ 拦截 | timing=1.1 拖垮综合分 |
| b3fb112c | 66.1 | **61.4** | ✓ 放行 | direction=63.1 够强，但有止损兜底 |
| e9842ba5 | 59.7 | **53.4** | ✗ 拦截 | timing+direction 双弱 |

4 笔亏损中 3 笔被新权重+新门槛直接拦截。

## 改动二：止损/止盈机制（`check_early_exits`）

### 病根

原系统持仓到市场结算（5 分钟到期），出场价要么 1.0（全赢）要么 0.0（全亏）。赢的利润取决于入场价（通常 +$0.3~0.5），输则固定 -$1.0。盈亏不对称要求 >65% 胜率才能盈亏平衡——当前 33% 远远不够。

### 方案：固定价差提前退出

新增配置参数（`config.py`）：

```python
STOP_LOSS_DELTA  = 0.10   # best_bid <= 入场价 - 0.10 时止损卖出
TAKE_PROFIT_DELTA = 0.15  # best_bid >= 入场价 + 0.15 时止盈卖出
```

### 逻辑流程（`execution/order_manager.py` → `check_early_exits()`）

```
每 2 秒（主循环频率）执行：
  遍历所有 open_positions:
    │
    ├─ 获取该持仓 token 的当前 orderbook
    │  （调用 fetch_order_book(session, pos.token_id)）
    │
    ├─ 读取 best_bid（当前能卖出的最优价）
    │
    ├─ 计算阈值：
    │    stop_price  = entry_price - STOP_LOSS_DELTA   (如 0.65 - 0.10 = 0.55)
    │    tp_price    = entry_price + TAKE_PROFIT_DELTA  (如 0.65 + 0.15 = 0.80)
    │
    ├─ 判断触发条件：
    │    best_bid <= stop_price  → 止损触发
    │    best_bid >= tp_price    → 止盈触发
    │    否则 → 继续持有
    │
    └─ 触发后执行退出：
         模拟模式：以 best_bid 为出场价计算盈亏，记录到 risk state
         实盘模式：提交限价卖单（SELL @ best_bid）
         日志标注退出原因：LOSS(STOP_LOSS) 或 WIN(TAKE_PROFIT)
```

### 止损止盈的具体效果示例

**止损场景**：买入 YES @ 0.65，市场走势不利
```
入场价 = 0.65，止损线 = 0.55
当 best_bid 跌到 0.55 时卖出
实际亏损 = (0.55 - 0.65) × shares = -$0.15
对比原来持仓到期全亏 = -$1.00
→ 亏损从 $1.00 缩小到 $0.15（减少 85%）
```

**止盈场景**：买入 YES @ 0.65，市场走势有利
```
入场价 = 0.65，止盈线 = 0.80
当 best_bid 涨到 0.80 时卖出
实际盈利 = (0.80 - 0.65) × shares = +$0.23
对比原来持仓到期全赢 = +$0.54
→ 利润略少，但确定性更高，不用赌最终结算
```

**不触发（继续持有到结算）**：
```
入场价 = 0.65
best_bid 在 0.56~0.79 之间波动
→ 不触发任何阈值，按原逻辑等 5 分钟结算（0.0 或 1.0）
```

### 调用位置（`main.py`）

在主循环中，`resolve_expired_positions()` 之前调用：

```python
# 检查止损/止盈
await order_manager.check_early_exits(session)
# 结算到期仓位
await order_manager.resolve_expired_positions()
```

先检查提前退出（止损/止盈），再处理到期结算。两者互不冲突——如果止损/止盈已平仓，`resolve_expired_positions()` 找不到该仓位会自动跳过。

## 改动三：方向信号降噪

### 病根

原参数在 5 分钟（300s）市场中窗口过短：
- 回看 120s = 市场生命周期的 40%，容易被瞬间波动误导
- 快线 30s / 慢线 90s 的 MA 交叉太灵敏，噪音大
- 平滑窗口仅 12s，来不及过滤掉单次异常

### 改动

| 参数 | 旧值 | 新值 | 原因 |
|------|------|------|------|
| `DIRECTION_LOOKBACK_SECONDS` | 120 | **180** | 回看扩到市场 60%，捕捉更完整趋势 |
| `DIRECTION_FAST_WINDOW` | 30 | **45** | 快线窗口拉长，减少毛刺 |
| `DIRECTION_SLOW_WINDOW` | 90 | **120** | 慢线窗口拉长，趋势基准更稳 |
| `DIRECTION_SMOOTH_WINDOW` | 12.0 | **20.0** | 平滑窗口加宽，降低单次噪音影响 |

逻辑不变，只调参数。更长的窗口意味着信号更稳定，但响应会略慢——在 5 分钟市场中这是合理的取舍。

## 风险与注意事项

1. **止损可能被"洗出"**：二元期权在结算前价格波动大，止损线太紧（delta 太小）可能导致正确方向的仓位被中途洗出。当前 0.10 delta 留了一定空间，后续可根据实战数据调整。
2. **止盈可能错过完整利润**：止盈 0.15 delta 意味着放弃持仓到期的最大利润（最高可达 0.5+），换取确定性。如果胜率提升，可考虑放宽或取消止盈。
3. **方向窗口加长 vs timing 限制**：回看 180s 但 timing 最早允许 40s 入场，意味着前 40s 的方向数据来自上一个市场窗口的 BTC 价格。这不是 bug——BTC 趋势跨市场边界连续。
4. **门槛 55 是否过严**：新门槛可能减少交易频次。如果发现交易量过少，可适当下调到 52~53。
