# 优化 012 — 胜率提升四策略：动量入场确认、价差/时机过滤、熔断机制

**日期**: 2026-07-07  
**触发**: 22笔仓位（#123–#144）分析，胜率仅 36.4%（8胜/14负）

---

## 根因分析

### 数据集概览

| 指标 | 数值 |
|------|------|
| 分析仓位数 | 22笔（#123–#144） |
| 胜 / 负 | 8 / 14 |

所有盈利仓位的 FORCE_EXIT 价格集中在 0.95–0.999，说明信号方向正确时回报很高。

|------|---------|--------|--------|---------|
| #128 | NO | 0.60 | 0.46 | **7秒** |
| #126 | NO | 0.58 | 0.46 | **7秒** |
| #134 | NO | 0.53 | 0.35 | **20秒** |
| #136 | NO | 0.59 | 0.46 | **24秒** |
| #133 | NO | 0.39 | 0.22 | **27秒** |

**根因**: 信号在 BTC 动量峰值处触发。此时 BTC 刚完成一波快速运动，预测市场价格尚未反映反弹，
但 BTC 已经反转。入场即追顶/追底，市场立刻反向，止损在秒级内被触发。

### 规律二：连续亏损聚集（市场状态切换）

```
按时间顺序：
123(W) 124(W) 125(W) → 126(L) 127(L) 128(L) 129(L) 130(L)
→ 131(W) 132(W) → 133(L) 134(L) 135(L) 136(L) 137(L)
→ 138(W) 139(W) → 140(L) 141(L) 142(L) 143(L) → 144(W)
```

每次连亏段内，模型方向判断系统性偏差——底层 BTC 趋势与信号预期方向相反。
连亏段平均长度 4–5 笔，需要熔断机制防止在坏状态下继续失血。

## 策略设计与实施

### 策略一：BTC 动量衰减入场确认（替代固定45秒延迟）

**最初方案**: 固定等待 45 秒  
**问题**: 对于本该盈利的仓位（如 #124 NO@0.56→0.99），45秒延迟意味着更高入场价（更差赔率）。
行情发展越快，代价越大——这是一个生硬的定时器，而非真正的信号质量判断。

**最终方案**: 等待 BTC 动量衰减

每个评估周期（约2秒）检查以下两个条件之一，满足则入场：

**条件A — 平稳**:
```
|BTC 近20秒涨跌幅| < 0.1%
→ 价格已企稳，可以安全入场
```

**条件B — 衰减**:
```
(近20秒涨跌速率) / (近60秒涨跌速率) < 40%
→ 初始冲击动能已见顶，当前动量不足平均的40%
```

**硬顶**: 超过 `ENTRY_MAX_WAIT_SECONDS = 60s` 仍不满足条件 → 强制入场（防止错过市场窗口）

**取消条件**: 等待期间代币价格相对信号价下跌超过 1.5% → 立即取消，不等满 60s

**对比效果**:

| 场景 | 固定45s | 动量衰减 |
|------|---------|---------|
| 稳健盈利仓位（BTC已平稳） | 延迟45s，入场价变差 | 立即入场，赔率不变 |
| 即时止损场景（BTC猛烈移动） | 等满45s才检查 | BTC动量过强时持续等待；BTC减速后进 |
| 快速发展好信号 | 45s后价格可能已涨很多 | 减速即入，不浪费时机 |
| 等待期间价格逆向 | 等满45s才发现 | 每2秒检查，逆向1.5%立即取消 |

**代码位置**:
- `config.py`: `ENTRY_BTC_MAX_VELOCITY`, `ENTRY_BTC_DECEL_RATIO`, `ENTRY_MAX_WAIT_SECONDS`
- `main.py`: `_btc_entry_ready()` 函数，`_pending_signals` dict，pending handler

---

### 策略二：时机分硬性下限（timing ≥ 35）

**依据**: 亏损仓位中 timing < 30 的（#127:20.0, #136:14.5）均亏损；盈利仓位最低 timing = 46.4。
时机分 < 35 的交易无一盈利，过滤精准无误杀。

**改动**:
```python
MIN_TIMING_FILTER_SCORE: float = 35.0   # (旧值 20.0)
MIN_TIMING_FILTER_SCORE_ENABLED: bool   # (改为默认 True)
```

---

### 策略三：价差分硬性下限（spread ≥ 65）

**依据**: spread < 65 出现在 4 笔亏损（47.2, 48.8, 64.9, 67.2）；盈利仓位 spread 均 ≥ 85。
低 spread 分代表流动性薄，滑点风险大。

**改动**:
- `config.py`: 新增 `MIN_SPREAD_FILTER_SCORE = 65.0`
- `main.py`: spread 通过 pass/fail 后，额外检查评分下限

---

### 策略四：连续亏损熔断机制（N=3，暂停300秒）

**依据**: 数据中有 3 段连亏聚集（#126-130, #133-137, #140-143），每段内的新信号均在继续押错方向。
连亏3笔后暂停1根K线（300秒），等待市场状态切换。

**改动**:
- `config.py`: `CIRCUIT_BREAKER_CONSECUTIVE_LOSSES = 3`, `CIRCUIT_BREAKER_PAUSE_SECONDS = 300.0`
- `execution/risk.py`: `RiskState` 新增 `consecutive_losses`, `circuit_breaker_until` 字段
- `record_close()`: 盈利→重置计数；亏损→递增计数，达到3笔触发熔断
- `can_trade()`: 熔断期间拒绝所有入场
